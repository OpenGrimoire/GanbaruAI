# Notes

The notes system is a local page and block editor for capturing thoughts, project context, daily logs, and long-form writing. SQLite is the canonical store. Markdown is derivative only: import, export, preview, or agent bridge output.

The model follows public Notion API concepts where they are useful locally: pages, parents, blocks, rich text arrays, child pagination, timestamps, trash state, and archive state. It does not depend on Notion services, private internals, or hosted infrastructure.

## Source of truth

Notes are stored in `ganbaru-ai.sqlite`:

- `notes_pages` stores page metadata, parent identity, title cache, properties, icon, cover, trash state, archive state, optional external source identity, and timestamps.
- `notes_blocks` stores the canonical block tree. Each row has a page id, parent identity, block type, type payload, rich text, plain text cache, child state, trash state, sort order, optional external source identity, and timestamps.
- `notes_databases` stores local child database metadata, parent identity, title rich text, optional icon and cover, timestamps, and optional external source provenance. `notes_data_sources` stores the initial data source for each source database, including title rich text and validated property schema JSON. Linked database blocks create another database shell and view row without duplicating the data source. `notes_database_views` stores local database views, starting with the first table view for the initial data source, and carries table property order, hidden properties, column widths, board grouping and card properties, gallery card settings, list grouping and row properties, calendar date property and range settings, timeline date property, grouping, and range settings, filters, sorts, and row open mode. `notes_data_source_relation_links` stores normalized database relation link rows derived from row page properties for backlinks, search, and target validation. `notes_data_source_rollup_cache` stores rebuildable computed rollup page property values and is invalidated when related source or target data changes. Formula properties store only their local expression in the data source schema and are evaluated from current row properties when rows load.
- `notes_page_templates` stores reusable page template metadata, page properties, icon, cover, source page identity, and timestamps. `notes_page_template_blocks` stores the canonical template block tree. Templates are SQLite data, not markdown or rendered HTML.
- `notes_page_history_settings` stores the local retention window for recoverable page versions. `notes_page_history_snapshots` stores compact SQLite snapshots of page metadata plus canonical block rows before recoverable page and block mutations. History snapshots are recovery data, not markdown or rendered HTML.
- `notes_page_icon_assets` stores metadata for local page icon images copied under the Ganbaru AI managed assets folder. Page rows reference those assets through the validated icon JSON payload.
- `notes_page_cover_assets` stores metadata for local and generated page cover images copied under the Ganbaru AI managed assets folder. Page rows reference those assets through the validated cover JSON payload.
- `notes_undo_state` stores a bounded page-local undo and redo stack for editor recovery. It is local operation state derived from canonical rows, not a second source of note content.

Markdown exports can be regenerated from SQLite. Markdown imports must be parsed into page and block rows before editing. If an exported markdown file changes outside the app, the app treats that as import input, not as authoritative state.

## Page model

A page has an object type, id, created and edited timestamps, parent, trash state, archive state, properties, icon, and cover. The first local page slice uses a title property named `title`, shaped as a Notion title rich text array, and also keeps a normalized title cache for fast sidebar reads. Page icons use the public Notion icon object shape, with editable emoji icons, native icon names and colors, reusable custom emoji, external HTTPS image icons, managed local image file icons, and null removal from the page header. Page covers use the public Notion file object shape, with editable external HTTPS image covers, imported Notion-hosted file objects, imported file upload references, managed local image file covers, generated local cover images, and null removal from the top of the page.

Parents are explicit objects:

- `workspace` for top-level pages.
- `page_id` for subpages.
- `block_id` for pages nested under blocks.

Workspace pages appear at the top level of the sidebar. Page-parented child pages appear under their parent page in the sidebar tree, with local expanded state that does not change the canonical page graph. The sidebar loads page metadata lazily: roots are loaded first, expanded page ids load their direct child page metadata, and selected pages load their ancestor path so navigation remains understandable without loading page block bodies. Breadcrumbs resolve the selected page's parent chain from SQLite even when ancestors are not loaded in the sidebar. Active ancestors are navigable, while archived, trashed, or missing ancestors stay visible with status text instead of pretending to be normal pages. Block-parented child pages remain addressable through breadcrumbs and visible child-page blocks until the sidebar can resolve loaded block ancestry across the whole workspace.

## Block model

Blocks are ordered children of a page or another block. The current local block registry is audited below against the actual Svelte UI and SQLite-backed behavior. Status terms are intentionally stricter than "type exists":

- Implemented means the current UI, persistence, tests, and docs are good enough for the block's present local scope.
- Broken is reserved for a known supported block whose current UI or persistence fails its documented scope. This audit found no broken rows.
- Planned means a first slice or preservation path exists, but expected editing depth remains tracked by later Notes checkboxes.
- Not started means the type is known from current Notion-shaped planning but is intentionally not registered or accepted as a first-class local block.

Until then, imports must preserve those source blocks as visible `unsupported` blocks instead of registering a partial local block type or migration.

Text-bearing blocks store public rich text arrays and block-level color in the block type payload. The editor currently supports text rich text, inline annotation rich text, inline equation rich text, safe hyperlink rich text, page mention rich text, and date mention rich text with local reminder metadata. Focused text blocks render stored bold, italic, underline, strikethrough, inline code, links, inline equations, page mentions, date mentions, text colors, and background colors inside the editable surface. Selecting text in a text block exposes a viewport-aware inline toolbar near the real selection for bold, italic, underline, strikethrough, inline code, inline equation, text color, background color, and link editing; the toolbar docks instead of overlapping text when the viewport is too narrow to float safely. The editor exposes a stable textbox label and placeholder instead of using block content as its label, links active mention and slash menus through ARIA controls, announces open menu state through localized live status text, reports the active mention option where available, and keeps keyboard focus rings visible on the editor, toolbar, menus, and link editor controls. Ctrl or Cmd+B, Ctrl or Cmd+I, Ctrl or Cmd+U, Ctrl or Cmd+Shift+S, and Ctrl or Cmd+E toggle bold, italic, underline, strikethrough, and inline code on the selected text, then keep the selected range stable when the rich editor can restore it. Markdown-style inline typing shortcuts convert `**bold**`, `*italic*`, `` `code` ``, and `~strikethrough~` into rich text annotations after the closing delimiter is typed, and they ignore ranges containing page mentions, date mentions, or inline equations instead of flattening those objects. Ctrl or Cmd+K opens link editing for the current selection or an existing link under the caret. Users can add, edit, or remove HTTP, HTTPS, and email links without replacing the whole block payload, and invalid schemes are rejected before storage. Editing local Notes links refreshes derived backlinks. The rich editor tracks plain-text selections across contenteditable rerenders, debounced saves, saved-block replacements, and focus recovery. Link edits restore the edited range, while operations that insert inline equations or mentions place the caret after the inserted object by design. Ctrl or Cmd+Shift+E converts selected text into a validated inline equation object, rejects empty or invalid selections with localized feedback, and places the cursor after the inserted equation. Typing `@` in a text block opens a mention picker backed by local page metadata and local date parsing for common inputs such as today, tomorrow, weekdays, ISO dates, and remind queries. Selecting a page inserts a validated page mention object with a local Notes page link. Selecting a date or reminder inserts a validated date mention object. IME composition leaves slash commands, mention replacement, inline markdown conversion, and debounced block saves idle until the browser commits the composed text. Pasting into the rich editor accepts validated plain text and sanitized rich HTML from browsers, document editors, and other Notes blocks. Rich paste preserves supported inline annotations and safe HTTP, HTTPS, and email links, removes scripts and unsafe link targets before persistence, and splits multiple pasted paragraphs into sibling blocks. Plain text edits around page mentions, date mentions, links, inline equations, and formatted spans preserve each rich text object when its visible label remains present, while edited or deleted labels degrade to plain text without flattening unrelated objects. Unknown supported-by-Notion fields can be preserved inside the payload only after validation.

Nested blocks are represented by parent rows, not by embedding children inside JSON. Child loading uses cursor pagination so large pages can stream in later.

Database templates are scoped to one local data source. Creating a template from a row snapshots that row's editable properties and loaded body block tree into canonical SQLite rows. Applying a template creates a new row page under the data source, remaps the stored block ids, copies body blocks into `notes_blocks`, derives the title from the requested row title, and replays stored properties against the current schema by property id so renamed properties still apply. One default template can be set per data source. Templates are exposed in the table view creation controls, and using no explicit template falls back to normal blank row creation.

Database button properties are local typed actions, not arbitrary automation blobs. The first supported action updates a property on the current row only. Button properties are rendered as derived read-only cell values, not stored row properties, and clicking a button routes through a Tauri command that reloads the current schema, validates the target row, requires confirmation when the button configuration asks for it, then applies the typed property update. Broad actions, destructive actions, webhooks, mail, and third-party integrations stay unavailable until each action family has a local schema, confirmation boundary, and tests.

## Editor behavior

The first serious Notes tab includes:

- Page sidebar with favorites, recents, a nested page tree, create, create subpage, select, rename, move, duplicate, archive, collapse, workspace search, and trash actions.
- Page templates section in the sidebar for saving the current page as a template, applying a template as a new page, renaming, updating from the current page, duplicating, and deleting templates.
- Archive view with archived-page search and unarchive.
- Trash view with trashed-page search, restore, and permanent delete.
- Backlinks disclosure under the page title for visible pages that reference the current page.
- Comments disclosure under the page title for page discussions and block comments.
- Page history disclosure under the page title for browsing prior page versions, previewing their blocks, copying blocks from them, restoring a version, and changing the local retention window.
- Page header icon picker for setting or removing emoji, native, custom emoji, external image, and managed local image page icons, mirrored in sidebar rows.
- Page cover banner for setting or removing generated, uploaded local, and external HTTPS image covers while preserving imported file and file upload cover references.
- Block editor with implemented text and navigation blocks plus the first-slice or preservation block surfaces listed in the block quality audit.
- Block handles with add block below, insert block type, turn into, color, copy link, duplicate, move to page, move within page, and delete actions.
- Nested block support through Tab and Shift+Tab.
- Sibling block reordering through handle actions and Ctrl or Cmd+Shift+ArrowUp or ArrowDown.
- Drag reordering, nesting, outdent, and move-to-page from the block handle, with visible drop targets.
- Enter behavior for splitting or creating sibling blocks.
- Backspace behavior for merging with the previous block or deleting empty blocks.
- Slash menu for block conversion, block actions, block colors, filtering, and recent commands.
- Viewport-aware inline formatting toolbar from selected text in editable text blocks, including inline equation conversion.
- Link editor from selected text, toolbar action, or Ctrl+K in editable text blocks.
- Page, date, and reminder mention menu from `@` in editable text blocks.
- Plus menu for inserting a chosen block type without typing a slash command.
- Markdown-like start shortcuts for common block types.
- Markdown-style inline rich text shortcuts for bold, italic, inline code, and strikethrough.
- Multi-line plain-text paste that creates sibling blocks instead of storing several paragraphs inside one block.
- Safe rich HTML paste that preserves supported inline formatting and links while creating sibling blocks for multiple paragraphs.
- Markdown-like paste prefixes for headings, lists, to-dos, toggles, quotes, dividers, and fenced code blocks.
- Ctrl or Cmd+Z, Ctrl or Cmd+Shift+Z, and Ctrl or Cmd+Y for page-local undo and redo across inline edits, block creation, conversion, movement, duplication, deletion, template insertion, button insertion, and block payload edits.

These behaviors are implemented as pure TypeScript planning helpers where possible. Svelte components adapt keyboard and focus events to those helpers, then persist changes through Tauri commands. Enter in a rich text block splits the current block at the selection boundary, drops the selected range when text is selected, keeps supported rich text objects on the correct side of the split, and appends the new sibling through the normal block children command. Paragraphs, bullets, numbered items, to-dos, and toggles continue as the same block type; headings, callouts, and quotes continue into a paragraph sibling. Empty bullets, numbered items, to-dos, toggles, callouts, and quotes convert back to paragraph instead of creating another empty block. Shift+Enter inserts a soft line break inside the current text, while code blocks keep Enter as a code newline and use Ctrl+Enter to create a paragraph sibling. Backspace in an empty text-editable block deletes that block unless it is the only remaining visible block, in which case the block is kept as an empty paragraph. If the deleted block has loaded direct child blocks, those child subtrees move to the deleted block's parent before the empty block is trashed. Backspace at the start of a non-empty text-editable block merges it into the previous compatible text-editable block, preserves rich text objects and annotations across the boundary, and moves loaded direct child blocks under the surviving block when it can own children. If the surviving block cannot own children, the moved child subtrees stay near the original source position instead of being trashed. Tab nests the focused block under the previous sibling only when that sibling can accept the source block type, and Shift+Tab outdents only when the destination parent can accept that source type. Page roots, column lists, tables, and tab label layers are protected from invalid keyboard moves before the Rust command boundary. Undo and redo record snapshot pairs at the same mutation boundaries as normal block commands. Typing and text-like repeated updates are grouped by block within a short time window, while formatting, links, mentions, equations, paste, structural block edits, template use, and button use remain discrete entries. The bounded stack is persisted per active page for practical crash recovery, and applying an entry reuses existing block rows through update, trash, restore, and move commands. The editor surface is split between the page shell, block list, block row chrome, text editor controls, card-like block editors, and media or layout-specific child components. The Notes store keeps its public API stable while delegating page preference persistence, focus request tokens, block tree selectors, debounced block persistence, undo state, and block actions to focused helper modules.

Sidebar navigation is planned from lazily loaded active page metadata plus local favorites, recents, and expanded-page metadata. Favorites keep explicit user order, recents exclude favorites and stale ids, and selected pages reveal their ancestor path without mutating the stored expanded list. Sidebar search switches from navigation sections to canonical SQLite search results, while Archive and Trash keep their own title filters over recoverable pages. Page row actions cover create child page, select, rename, move, duplicate, archive, trash, favorite toggle, and collapse. Rename focuses and selects the title field as soon as editing begins. Rows whose parent page is missing or in Trash show a warning state instead of silently pretending the page is a normal root. Long page action menus, searchable destination pickers, Archive restore rows, and Trash restore or permanent-delete rows remain reachable at the app's smallest supported window widths.

## Manual rich editor acceptance checklist

Rich editing is manually accepted only when every item below passes on a current app build. Use a scratch Notes page with at least two other pages available for page mention testing. After each step that changes content, wait for the visible edit to settle before moving to the next step.

- [ ] Typing: create a blank paragraph block, type `Plain text survives`, click another block, then return to the paragraph. The text remains visible in the same block, the caret can be placed inside it, and no extra block is created.
- [ ] Selection: select `Plain` inside the paragraph, press the Right Arrow key once, then click back into the word. The selection clears only when the key or click would normally clear it, and the caret does not jump to the end unexpectedly.
- [ ] Ctrl or Cmd shortcuts: select `Plain`, press Ctrl or Cmd+B, Ctrl or Cmd+I, Ctrl or Cmd+U, Ctrl or Cmd+Shift+S, and Ctrl or Cmd+E one at a time. Each shortcut toggles bold, italic, underline, strikethrough, or inline code visibly on the selected range; pressing the same shortcut again removes that style without changing the surrounding text.
- [ ] Toolbar formatting: select `text`, use the inline toolbar buttons for bold, italic, underline, strikethrough, inline code, inline equation, link, and text or background color. The toolbar stays usable after pointer activation, the selected range receives the requested formatting, and the selection is not lost before the command applies.
- [ ] Links: select `survives`, press Ctrl or Cmd+K, enter `https://example.com`, and apply. The selected text becomes a visible link. Open the link editor again from the caret or toolbar, change the URL to `mailto:test@example.com`, apply it, then remove it. Unsafe schemes such as `javascript:alert(1)` are rejected and do not persist.
- [ ] Mentions: type `@` in a paragraph, filter to an existing page, select it from the menu, then type ` @tomorrow` and select the date result. Both inserted mentions render inline, the caret lands after the mention, and editing text around the mention preserves the mention while its visible label remains unchanged.
- [ ] Equations: select `x=1`, press Ctrl or Cmd+Shift+E, and confirm the selection becomes an inline equation. Repeat with an empty selection and with text containing an unsupported control character; the editor shows useful feedback and does not store an invalid equation.
- [ ] Paste: paste rich text containing bold, italic, an HTTP link, multiple paragraphs, a `<script>` tag, and a `javascript:` link into a paragraph. Supported formatting and safe links are preserved, multiple paragraphs become sibling blocks, and unsafe markup or unsafe URLs are removed.
- [ ] Undo: after typing, formatting, link editing, mention insertion, equation insertion, paste, and a block duplicate or delete action, press Ctrl or Cmd+Z repeatedly. Each operation reverts in a predictable group without corrupting nearby rich text objects.
- [ ] Redo: after undoing the operations above, press Ctrl or Cmd+Shift+Z or Ctrl or Cmd+Y repeatedly. Each operation reapplies in order, with visible rich text, links, mentions, equations, and block changes restored.
- [ ] Reload persistence: after completing the steps above, switch to another page and back, then fully reload or restart the app. The paragraph text, formatting, links, mentions, equations, and pasted sibling blocks are still available from SQLite-backed Notes data. Ctrl or Cmd+Z can still undo the latest recoverable page-local operation if the undo stack was not intentionally exhausted before reload.

## Manual block editing acceptance checklist

Block editing is manually accepted only when every item below passes on a current app build. Use a scratch Notes page with at least three paragraph blocks, one bulleted item, one to-do, one toggle, one nested child block, and one other active Notes page available as a move target. After each step that changes content, wait for the visible edit to settle before moving to the next step.

- [ ] Enter: place the caret in the middle of a paragraph containing `Alpha Bravo`, press Enter, and confirm the block splits into `Alpha` and `Bravo` with focus in the new second block. Repeat at the end of a paragraph, a bulleted item, a numbered item, a to-do, and a toggle; each creates the expected sibling type. Press Enter in an empty list-like block and confirm it becomes an empty paragraph instead of creating another list item.
- [ ] Shift+Enter: place the caret inside a paragraph and press Shift+Enter. A soft line break appears inside the same block, no sibling block is created, and the caret remains after the inserted line break.
- [ ] Backspace: create an empty paragraph between two text blocks, focus it, and press Backspace. The empty block is removed and focus moves to the intended neighboring block. Put the caret at the start of a non-empty paragraph after another compatible text block, press Backspace, and confirm the two blocks merge without losing rich text. Repeat with the only visible block on a page and confirm it is preserved as an empty paragraph.
- [ ] Tab and Shift+Tab: focus the second paragraph under a valid previous sibling, press Tab, and confirm it nests under that sibling. Press Shift+Tab and confirm it returns to its original parent. Try the same from a table row, column surface, tab label, and page root edge where available; invalid moves must do nothing visible and must not corrupt the tree.
- [ ] Slash: type `/` at the start of an empty paragraph, filter to `heading`, choose a heading, and confirm the block converts while focus remains on it. Open slash again, run duplicate, delete, color, and copy link actions where available, and confirm they reuse the same behavior as the block handle actions. Type `/` in the middle of normal text and during active IME composition; the menu must not open unexpectedly.
- [ ] Plus: use the plus control beside a focused block to insert a paragraph, heading, to-do, toggle, table, column layout, tab block, divider, code block, and child page where available. Each inserted block appears below the source block, invalid internal structural rows are absent from the menu, and focus moves to the inserted editable block or first editable child surface.
- [ ] Handles: open the block handle menu from a text block on desktop width and narrow width. The add, turn into, color, comment, copy link, duplicate, move within page, move to page, and delete actions are reachable without layout shift. Copy link and color keep useful feedback, while structural actions close the menu and restore focus or highlight through the normal operation target.
- [ ] Drag: drag a paragraph before and after another paragraph, then drag it under a sibling to nest, then drag it left to outdent. The drop target is visible before release, the persisted block position matches the target after release, and focus returns to the moved block. Drag the same block onto another page in the sidebar and confirm the source page reloads with the block removed.
- [ ] Copy: select two adjacent blocks with Shift+Down or pointer selection, press Ctrl or Cmd+C, and paste into a plain text field outside Notes. The clipboard contains readable plain text in block order. Return to Notes and confirm the selected blocks remain unchanged.
- [ ] Paste: after copying selected Notes blocks, focus a later paragraph and press Ctrl or Cmd+V. The copied root blocks and their loaded children are duplicated after the target block, rich text is preserved, and focus moves to the first pasted block.
- [ ] Duplicate: duplicate one block from the handle menu, then select multiple adjacent blocks and press Ctrl or Cmd+D. In both cases the duplicate appears immediately after the source or selected range, loaded children are preserved, comments remain attached or duplicated according to the operation, and focus moves to the first duplicate.
- [ ] Move to page: open the block handle Move to page picker, search for another active page, move through destinations with Arrow Up and Arrow Down, and press Enter. Confirm the picker shows recent destinations and nested page context, excludes the current page, and excludes child-page destinations inside the moved subtree. The moved block subtree disappears from the source page, the destination page receives it at the bottom, and the source page focuses the nearest surviving block.
- [ ] Delete: delete one block from the handle menu, then select multiple blocks and press Delete or Backspace. The selected root subtrees disappear, loaded children disappear with their roots, the only remaining visible block on a page is protected, and Ctrl or Cmd+Z restores the deleted content in the expected place.
- [ ] Focus recovery: after creating, splitting, merging, moving, duplicating, converting, using a template, using a button, switching pages, opening a page link, opening a block link, deleting a block, and moving a block to another page, confirm the intended block receives keyboard focus when editable or a visible focus highlight when it is a non-text or layout block.

Block handles reserve their left rail width so icons do not shift the row when they appear, gain larger touch targets on narrow or touch-like layouts, and keep the action menu clamped inside the viewport. The plus control opens the shared insert catalog. The drag handle opens turn into, color, comment, copy link, duplicate, sibling move, move to page, and delete actions. Copy link and color actions keep the menu open for feedback or repeated color changes; structural actions close it and return focus through the editor's normal operation targets. Delete uses the same undo-backed block operation as keyboard deletion, so the user can recover it with page-local undo.

Multi-block selection is page-local UI state over the currently rendered block rows. Pressing Escape from a focused block selects that block; Shift plus Up or Down expands the selected range through the rendered order; Shift-click extends an existing range; dragging from the block handle rail selects the rows crossed by the pointer. Selected rows keep their state while the editor scrolls because the range is stored by block id. The selectable order comes from rendered rows, so visible nested blocks participate, while hidden table row records, column structural records, inactive tab panels, and tab label internals are not selected as document rows. A selected-block toolbar and keyboard shortcuts support copy, cut, paste, duplicate, sibling move, and delete for selected ranges. Ctrl or Cmd+C writes plain text to the system clipboard and keeps an internal canonical block clipboard for Notes paste. Ctrl or Cmd+X stores the same internal block clipboard, then trashes the selected root subtrees through a Rust transaction. Ctrl or Cmd+V pastes the internal clipboard after the focused block by duplicating the stored source subtrees through a Rust transaction. Ctrl or Cmd+D duplicates the selected root subtrees in place. Delete or Backspace trashes the selected root subtrees. Ctrl or Cmd+Shift+Up and Ctrl or Cmd+Shift+Down move selected root siblings as a group when all roots share a parent and the move target is valid. The backend rejects cycles, invalid parent shapes, duplicate ID maps, and insertion anchors inside a moved subtree. Nested children move or duplicate with their selected roots, rich text payloads stay canonical, block comments stay attached when blocks move, and duplicated blocks receive duplicated block comment threads.

Duplicating a block clones the selected block subtree through a Rust transaction. The frontend generates the duplicate IDs for the loaded subtree, and the backend validates that the ID map exactly matches the source subtree before inserting rows.

Moving a block up or down reorders it inside its current sibling group through the same Rust move command used by nesting and outdent. The frontend plans the move from the loaded block graph, flushes any pending save for the moved block, persists the new parent and adjacent block position in SQLite, reloads the visible tree, and restores focus to the moved block. This keeps nested block subtrees attached to the moved parent.

Dragging a block from its handle uses a pure move planner before it crosses the command boundary. The editor supports dropping before or after valid targets, nesting inside a target that can own the source block type, outdenting by dragging into the left outdent zone, and dropping a loaded block onto another sidebar page. Valid before and after drops show a thin line, valid nesting highlights the target block surface, valid outdent shows the line at the destination parent depth, and valid page drops highlight the destination sidebar row. The planner rejects cycles, table rows, columns, invalid parent shapes, current-page page drops, child-page self drops, and loaded descendant page targets before showing a drop target. The store flushes pending block saves before every drag-backed structural move, then persists the new parent and adjacent block position through the Rust move command. Rust validates the same constraints against SQLite, including destination parent acceptance, descendant cycles, destination pages inside the moved subtree, and `after` or `before` anchors that are outside the destination parent.

The block handle's Move to page action opens a searchable destination picker backed by active non-trashed Notes pages. The picker shows recent destinations first, keeps nested page context visible as a parent path, supports Arrow Up, Arrow Down, Home, End, Enter, and Escape, and moves the selected block subtree to the bottom of the destination page through the same Rust move command used by drag-to-page. The current page is excluded because same-page reordering has dedicated controls, and child-page blocks cannot be moved into their own page or into loaded pages contained by their subtree. After the move, the source page reloads so the removed block disappears and the page list refreshes edited timestamps.

Focus recovery is deterministic after block and page operations. Creating, splitting, pasting, duplicating, template use, and button use focus the first inserted block when one exists, otherwise the triggering block remains highlighted. Converting keeps focus on the converted block, including divider and generated layout surfaces. Deleting a block or moving it to another page focuses the nearest previous surviving rendered block, then the next surviving block, then clears focus if no rendered block remains. Merging focuses the surviving target block. Moving, nesting, outdenting, reordering, and dragging inside the same page focus the moved block. Switching pages and opening page links focus the first visible block, while opening a block link focuses the linked visible block.

Block links are local anchors built from the Notes page id and block id. The block action menu and slash menu can copy a link to the clipboard. Opening that link switches the app to the Notes tab, loads the target page, scrolls the target block into view, and focuses it. Page mention links use the same local Notes hash without a block id and open the target page. Inline text hyperlinks use public rich text `text.link` and `href` fields, validate allowed URL schemes before storage, normalize bare email addresses to `mailto:` links, and refresh derived backlinks when edited. Links use stable SQLite ids when they target local Notes pages or blocks, so renaming a page or editing block content does not invalidate local block links.

Backlinks are derived from canonical block references and normalized database relation links, not manually maintained. The backlink list includes visible active pages that reference the current page through paired child-page blocks, local Notes URLs in rich text links, page mention rich text payloads, or relation properties on active database row pages. Trashed source blocks, trashed or archived source pages, and relation rows whose source or target data source is inactive are hidden from the backlink list. Selecting a backlink opens the source page and focuses the source block or relation source page.

Comments are SQLite-backed discussions modeled after public Notion comment objects. A comment thread attaches to either the current page or a visible block, stores a discussion id, rich text body, local author display metadata, status, timestamps, and soft-delete state. The page header comments disclosure lists open threads by default, can include resolved threads, supports replies, edit, soft delete, resolve, and reopen, and block handles can start a block-anchored comment. Selecting text in a rich text block exposes an inline comment toolbar action that creates a block thread with a normalized text-range anchor. The editor highlights anchored text, resolved anchors use a muted highlight, and the comments panel labels inline threads by the selected text. Anchors store selected text plus nearby prefix and suffix context, so the UI can relocate the highlight after nearby edits when the selected text still exists. If the anchor text can no longer be found, the thread remains available and the comments panel reports that the anchor is missing. Comment rich text validates the same text, page mention, date mention, and reminder mention objects supported by the editor. User mentions, unread state, attachments, notification delivery for reminder metadata, and local notification settings remain planned.

The slash menu uses one command catalog for block conversion, block actions, block colors, filtering, and session-local recent commands. Rich text blocks open it only from an intentional `/` typed at the start of an empty block. Pasted text, regular typing inside existing content, and active IME composition do not open it. While the menu is open, typed query text filters against cached command aliases such as duplicate, delete, red background, or table of contents. Arrow Up and Arrow Down move the active command, Enter and Tab select it, Escape closes it, and pointer hover or click can select the same active command list. Choosing a typed slash block command clears the slash query before conversion. Other turn-into paths preserve supported rich text objects unless their command explicitly requests empty text. Action commands reuse the same duplicate, move, delete, and copy-link paths as block handles. Color commands appear only for blocks whose payload can store a Notion color value.

The plus menu uses the same shared insert command catalog as the slash menu's block command group. It can insert user-created block types below the current block without typing slash, including text, headings, toggle headings, lists, to-dos, toggles, callouts, child pages, local databases, generated navigation blocks, layout first slices, media URL blocks, bookmarks, link previews, template buttons, local button blocks, embeds, equations, dividers, and code. Internal structural rows such as table rows and columns are excluded because they are created through their parent table or column-list blocks. Preservation-only blocks such as synced block duplicates and unsupported blocks are excluded until their full creation semantics exist locally. Plus-created tables include default rows, column layouts include two editable columns, tab blocks include default labels and editable first-tab content, child pages create the paired SQLite page row and child-page block at the active sibling position, and local databases create their database, initial data source, first table view, and child-database block through one Rust transaction. Focus moves to the inserted editable block, first table cell, first column paragraph, first tab content block, divider control, new child-page body, or new local database block as appropriate. The menu is pointer-first, uses localized block labels, and clamps its width and height inside narrow viewports.

Toggle blocks use the public Notion `toggle` payload shape for rich text and color, plus a local `ganbaru_open` display flag so closed toggles stay closed after reload. Toggle children remain normal block rows in SQLite. Closing a toggle hides its descendants in the flattened editor view without deleting or moving them. Users can create toggles from the slash menu, convert blocks to toggles, type `>` followed by space, and press Ctrl+Enter while focused in a toggle to open or close it.

Toggle headings use the public heading 1 through heading 4 payload shape with rich text, color, and `is_toggleable`, plus the local `ganbaru_open` display flag. Normal heading blocks cannot own children. A heading can own child block rows only when `is_toggleable` is true, and the backend rejects appends, moves, or updates that would leave children under a non-toggleable heading. Closed toggle headings hide descendants in the flattened editor view without deleting or moving them. Users can create toggle headings from the slash menu and press Ctrl+Enter while focused in a toggle heading to open or close it.

Callout blocks use the public Notion `callout` payload shape for rich text, icon, and color. Ganbaru AI persists the callout icon in the block payload and renders the current default native info icon in the editor. Callout children remain normal block rows in SQLite, so a callout can contain nested notes without embedding child arrays inside JSON. Users can create callouts from the slash menu or convert existing blocks to callouts.

Child-page blocks use the public Notion `child_page` payload shape with a title string. Ganbaru AI stores the child page as a normal page row and stores a paired `child_page` block in the parent document using the same id. Converting a block to a child page creates the nested page, moves existing child blocks into the new page body, opens that page, and keeps future page renames and trash or restore operations synchronized with the parent block. Creating a subpage from the sidebar uses the same Rust page-create command boundary, inserts the paired child-page block into the parent document, opens the new page, and expands the parent row.

Child-database blocks use the public Notion `child_database` payload shape with a title string, plus local `database_id`, `data_source_id`, and `view_id` references when the database is created inside Ganbaru AI. Creating a database from the slash menu, plus menu, or block conversion inserts the visible child-database block, a `notes_databases` row, one `notes_data_sources` row, and one table `notes_database_views` row in a single Rust transaction. Creating a linked database view inserts another visible child-database block plus a separate `notes_databases` shell and `notes_database_views` row, but it keeps the same `data_source_id` as the source database. Board, gallery, list, calendar, and timeline views are created lazily for the same data source when the user opens their tabs. Imported title-only child-database blocks remain visible preservation placeholders.

Local child databases expose a property editor, table view, board view, gallery view, list view, calendar view, and timeline view on the block surface. The editor loads the local data source schema from SQLite, supports title, rich text, number, select, multi-select, status, date, checkbox, URL, email, phone, files, people, created time, created by, last edited time, last edited by, unique ID, place, relation, rollup, and formula schema properties, and saves a canonical Notion-shaped property object back to `notes_data_sources`. Linked database views load the same schema and row pages as the source database, while each linked block reads and writes the `notes_database_views` row identified by its own `view_id`. The first table view stores the visible column order, hidden property ids, column widths, filters, sorts, and row open mode in `notes_database_views`. The board view stores its grouping property, group order, hidden group ids, card property ids, filters, sorts, and row open mode in its own `notes_database_views` row. The gallery view stores its cover source, optional files cover property, visible card property ids, card size, fit image behavior, filters, sorts, and row open mode in its own `notes_database_views` row. The list view stores its optional grouping property, group order, hidden group ids, visible row property ids, filters, sorts, and row open mode in its own `notes_database_views` row. The calendar view stores its date property, visible range, visible row property ids, filters, sorts, and row open mode in its own `notes_database_views` row. The timeline view stores its date property, optional grouping property, group order, hidden group ids, visible range, visible row property ids, filters, sorts, and row open mode in its own `notes_database_views` row. The required title property cannot be hidden, deleted, or converted to another type. Select, multi-select, and status properties store local option ids, labels, colors, and status groups; number properties store display format; unique ID properties store an optional prefix. Relation properties store a target data source id and optional synced inverse property metadata, reject missing target data sources, and rebuild link rows when the schema changes. Rollup properties store the relation property id and name, target property id and name, and calculation function. They reject missing relations, missing target properties, incompatible calculation functions, and rollups that target computed properties. Formula properties store an expression string, parse it into a bounded local AST, reject unknown property dependencies and formula cycles, and evaluate through the Rust expression engine. The formula language supports literals, `prop("Name")`, arithmetic, comparisons, boolean operators, `if`, `empty`, `format`, `length`, `contains`, case conversion, numeric helpers, and basic arithmetic functions. It does not use JavaScript `eval`.

Database rows are real Notes pages parented by the local data source. Creating a row inserts a `notes_pages` row with `parent_type = 'data_source_id'`, stores Notion-shaped page property values derived from the current data source schema, and creates a normal first paragraph body block in `notes_blocks`. Row pages are hidden from the sidebar root because the database view owns their navigation surface, but they can be opened as full pages or previewed in the table, board, gallery, list, calendar, or timeline side panel from the child-database block. Linked database views show the same row pages because they point to the same data source, but their filters, sorts, visible properties, grouping, ranges, and row open modes are independent. Once open, row page bodies use the same rich block editor as any other Notes page. Table cell edits update the row page property values through Rust commands, then reload the filtered and sorted table rows. Relation table cells show linked row titles, let users add or remove target rows from the configured data source, reject targets outside that data source, rebuild normalized link rows, and sync the inverse property when a valid two-way relation is configured. Rollup cells are computed when database rows are loaded, read from relation target pages, and never saved as canonical `notes_pages.properties` values. Formula cells are computed after relation titles and rollups are hydrated, can depend on other formulas through a checked dependency graph, display runtime errors as string formula values, and are never saved as canonical `notes_pages.properties` values. The rebuildable rollup cache is invalidated by schema changes, relation edits, row property edits, and row page trash, archive, restore, or delete operations. Board card moves update the selected group property for select, multi-select, status, checkbox, and date groups, then reload the filtered and sorted board groups. Gallery cards use page covers, files property previews, or no preview; they reload through the gallery view's filters and sorts and can show a user-selected set of card properties. List rows keep the title first, show selected properties compactly to the right, and can be grouped by locally groupable properties without changing row page storage. Calendar rows use a selected date property, filter rows by overlap with the visible month range, display date ranges on each covered in-month day, and create row pages from day cells with that date property prefilled. Timeline rows use a selected date property, filter rows by overlap with the visible range, render horizontal date spans, support optional grouping by locally groupable properties, create rows from date headers, and resize row ranges through date inputs that write the same canonical date property value as table cells. People and relation-shaped groups can be displayed when data already has those values, but drag writes stay disabled until local people editing and group-safe relation writes exist. Text, rich text, number, checkbox, select, multi-select, status, date, URL, email, phone, place, and relation cells are editable in this first slice; files, people, created time, created by, last edited time, last edited by, and unique ID cells are read-only until their local semantics are explicit, while rollup and formula cells are read-only computed outputs. Row pages participate in page search, page duplication, Trash, restore, and permanent deletion through the existing page lifecycle. Database item templates remain planned as a later database slice.

Favorites and recents are local navigation metadata stored outside the canonical page graph. Favoriting a page pins it in the sidebar and shows a star in the page header and sidebar row. Opening or creating a page records it in recents so frequently used pages stay reachable without changing page parents, page sort order, or block content.

Sidebar search queries canonical SQLite data through the `notes_search` command. Results include active page title matches, active block plain-text matches, non-deleted comment text matches, and active database row pages that link to matching relation target titles, with snippets and result type labels. Page results open the page, block results open the page and focus the matching block, relation-derived page results open the source row page, and block-comment results focus the commented block when the thread target still exists. The first search slice uses bounded SQLite text matching over canonical columns and normalized relation links; a future FTS cache can replace the query internals without changing the result contract.

Duplicating a page copies the source page row, page icon, cover, visible block tree, and nested child pages through one Rust transaction. The duplicate gets fresh page and block ids, does not inherit import provenance, and keeps child-page block ids paired with their duplicated page rows. Workspace pages duplicate as new top-level pages. Nested pages duplicate beside the source child-page block in the same parent. Database row pages duplicate under the same data source, preserve row property values, and skip child-page block creation because the database view is their visible navigation surface.

Page templates are global Notes templates modeled after reusable Notion page templates, not database-scoped or repeating templates. Creating or updating a template snapshots the current page's properties, icon, cover, and root block tree into `notes_page_templates` and `notes_page_template_blocks`. Applying a template creates normal `notes_pages` and `notes_blocks` rows through a Rust transaction, sets the applied page title when the user supplies one, and leaves the template rows unchanged. Renaming, duplicating, and deleting templates affect only the template records. Child-page template blocks create paired local child pages with default empty bodies in this first slice; full subpage body snapshots remain future work.

Page history is a local recovery surface for Notes pages. Mutations that change page details, page placement, archive or trash state, child-page links, or block content record a deduplicated snapshot of the affected page before the mutation commits. Rapid editor mutations, including normal block text edits, Enter-created rows, and immediate empty-row cleanup, coalesce into one short edit-session checkpoint instead of creating a separate version for every debounced write. A later edit after the idle window records a new checkpoint. The page header history disclosure lists available versions, shows the snapshot reason, timestamp, and block count, and loads a read-only preview of the version's page title and block tree. Copying from a version appends fresh block rows to the current page and creates paired child-page rows for copied child-page blocks. Restoring a version saves the current page to history first, then replaces the current page's title, properties, icon, cover, trash/archive flags, and page body blocks with the snapshot. Restoring does not move the page back to an old parent; page location stays under the current page graph so a history restore cannot unexpectedly move navigation context. Child page bodies keep their own page history, while restored or copied child-page link blocks create paired local child pages with default empty bodies when a matching active child page is missing. The retention selector stores a local window in days or forever, and pruning deletes snapshots older than the configured window.

Moving a page changes the page parent through a Rust transaction and keeps the paired child-page block synchronized with the destination. Moving under another page creates or restores the paired child-page block at the bottom of that destination page. Moving back to the workspace hides the paired child-page block so the page becomes a top-level sidebar item. Page row actions use the same searchable destination picker shape as block moves, including recent destinations, nested context, search, and keyboard navigation. The picker excludes the current parent where practical, and the command rejects block parents for the sidebar move action, missing or inactive destination pages, moving a page under itself, and moving a page under a descendant reachable through page parents or child-page blocks.

Archived pages keep a separate `archived` state in SQLite and are hidden from the normal page list, favorites, recents, active sidebar search, active page loading, active parent validation, and parent-page document body without entering Trash. The page action menu confirms before archiving a page. The sidebar exposes an Archive view that lists archived page metadata, supports local search, and unarchives a page through the Tauri command boundary. Unarchived pages are selected and loaded immediately. If an unarchived page's stored parent is missing, archived, or in Trash, the page is promoted to the workspace and the stale paired child-page block stays hidden. Trashing a page clears its archive state so Trash remains the single recovery surface for deleted pages.

Breadcrumb blocks use the public Notion `breadcrumb` empty payload shape. The rendered path is generated from the current local page graph instead of being stored as duplicated text, so nested pages update breadcrumbs automatically when page titles or parents change. Breadcrumbs use the backend-resolved page chain for loaded and unloaded ancestors, keep active ancestors clickable, and label archived, trashed, or missing ancestors without opening them through the active editor path. Users can create breadcrumbs from the slash menu or convert existing blocks to breadcrumbs.

Table of contents blocks use the public Notion `table_of_contents` payload shape with block-level color. The rendered heading index is generated from the current local block graph instead of being stored as duplicated text, including heading levels 1 through 4. Users can create a table of contents from the slash menu, convert existing blocks to it, and use generated entries to focus the matching heading block.

Column list blocks use the public Notion `column_list` empty payload shape. Column blocks use the public Notion `column` payload shape with optional `width_ratio`. Ganbaru AI stores columns as internal child blocks under the column list, and the editable content inside each column remains normal child blocks in SQLite. The editor renders the column list as one layout surface, hides internal column container blocks from the main page flow, stacks columns when the layout no longer fits, and keeps keyboard deletion and merge behavior scoped to the focused column. Users can create a default two-column layout from the slash or plus menu, add columns up to the local practical control limit, remove columns while moving their child blocks into a neighboring column, move columns left or right, resize columns through persisted width sliders, and drag existing blocks into a target column drop zone. Nested child block subtrees stay attached to their blocks during column moves and removal cleanup.

Table blocks use the public Notion `table` payload shape with `table_width`, `has_column_header`, and `has_row_header`. Table row blocks use the public Notion `table_row` payload shape with `cells`, where each cell is a rich text array. Ganbaru AI stores rows as normal child block rows under the table block, but the editor renders them as one table surface instead of exposing row blocks as standalone document rows. Users can create a default local table from the slash menu, edit cells through rich-text-preserving contenteditable cells, navigate cells with Tab, Shift+Tab, Enter, Shift+Enter, and arrow keys, and add or remove rows and columns with table controls. The table keeps header flags while local width changes, remains horizontally scrollable at narrow widths, and leaves database-style table views to later P2 database work.

Tab blocks use the public Notion `tab` empty payload shape. Direct children of a tab block are paragraph rows that act as tab labels; their rich text stores the visible label, their optional paragraph icon stores the tab icon, and their child rows store the tab panel content. The editor renders the tab block as one layout surface, hides label paragraphs from the main page flow, and shows the active tab's child blocks as normal editable Notes content. Users can create a default local tab group from the slash or plus menu, rename the active tab inline, choose supported emoji or native icons, add tabs up to the local practical control limit, remove tabs while moving their child content into a neighboring panel, move tabs left or right, and drag existing blocks onto tab triggers to move them between panels. Nested child block subtrees stay attached to their blocks during tab moves and removal cleanup.

Image, video, audio, file, and PDF blocks use public Notion file object source shapes. Ganbaru AI currently supports editable external HTTPS file URLs for new local blocks and validates imported Notion-hosted `file` and `file_upload` source objects. Non-empty external URLs must match the block kind, such as image extensions for image blocks, audio extensions for audio blocks, video extensions or supported YouTube URLs for video blocks, `.pdf` for PDF blocks, and any HTTPS URL for file blocks. The editor keeps local drafts while users type, explains invalid URL, non-HTTPS URL, and unsupported type states before the SQLite command boundary, stores captions as rich text arrays, supports an optional file name on file blocks, derives the plain text cache from captions and source identity, renders native previews only for directly previewable image, video, audio, and PDF URLs, and opens all media only after explicit user action. YouTube video links and generic file links render a local placeholder rather than an embedded remote player. Caption and display-name edits preserve imported `file` and `file_upload` source objects unless the user supplies a replacement external URL. Local file attachment storage and fuller offline behavior remain planned and must use the Ganbaru AI assets/file model rather than raw untracked paths.

Bookmark blocks use the public Notion `bookmark` payload shape with a URL string and caption rich text array. Ganbaru AI stores and edits the URL and caption locally, derives the plain text cache from both fields, and does not fetch remote preview metadata automatically. The open button launches only HTTP and HTTPS URLs through the platform opener.

Link preview blocks use the public Notion `link_preview` payload shape with a URL string. Public Notion integrations can retrieve these blocks but cannot create or append them through the public API. Ganbaru AI still supports local creation because Notes are not a hosted Notion connection: it stores and edits the originally pasted URL, derives the plain text cache from that URL, renders a local card from URL parts only, and avoids automatic remote metadata fetches. The open button launches only HTTP and HTTPS URLs through the platform opener.

Synced blocks use the public Notion `synced_block` payload distinction between originals and duplicates. Original synced blocks store `synced_from: null` and can own normal child block rows in SQLite. Duplicate synced blocks store `synced_from.type: "block_id"` with a source block id and render as visible reference placeholders. The editor clearly labels original and duplicate shapes, preserves imported references, keeps duplicates from exposing editable child rows, and leaves move, duplicate, comment, copy-link, delete, and page move as local block operations. Fanout editing across synced copies is not supported yet because the public API does not support synced block content updates and Ganbaru AI has not introduced an independent local sync graph for this block type. Creation from insert menus remains unavailable until local duplicate creation semantics are designed.

Template button blocks use the public Notion `template` payload shape with a rich text title. Their reusable content remains normal child block rows under the template block, not embedded child JSON in the payload. The editor renders a template control strip above the rich title editor with reusable child count, an add-content action that appends an editable paragraph child under the template, and a use action that duplicates the loaded child subtrees below the template through the existing duplicate and move commands. Child-page descendants intentionally disable the use action with visible messaging because page duplication and page link pairing need separate semantics. The public Notion API no longer supports creating template blocks, but Ganbaru AI keeps local template block creation because the local SQLite block graph is the source of truth and no Notion service is involved.

Button blocks use a Ganbaru AI local payload because Notion's public block API does not expose a supported `button` payload even though the Notion product supports page buttons. The local payload stores a rich text label, an optional icon, and a bounded action list. The first supported action is `insert_blocks`, which duplicates the loaded child block subtree from under the button to the configured target position. New local buttons default to inserting below the button. Button action children remain normal child block rows in SQLite. The editor renders a button control strip above the rich label editor with a source child count, native icon and icon-color controls, an insert-position selector, an add-source-block action, a run button, and disabled broad-action choices for unsupported database edits, webhooks, and destructive automations. Users can edit source content as normal child blocks under the button. Child-page descendants intentionally disable the run action because paired page creation and page-link duplication need separate semantics. External actions such as webhooks, mail, Slack, broad database edits, and destructive automations remain unsupported until they have explicit local schemas, user prompts, and permission boundaries.

Embed blocks use the public Notion `embed` payload shape with a URL string. Ganbaru AI stores and edits the URL locally, derives the plain text cache from the URL, and renders a local hostname label instead of fetching remote preview metadata. The open button launches only HTTP and HTTPS URLs through the platform opener.

Equation blocks use the public Notion `equation` payload shape with a KaTeX-compatible expression string. Ganbaru AI stores and edits the expression locally, derives the plain text cache from the expression, and renders a dependency-free formula surface until a vetted math renderer is approved.

Unsupported blocks use the public Notion `unsupported` payload shape and preserve the informational `block_type` string from imports when present. Ganbaru AI also allows validated local provenance fields, raw source metadata, and import warnings in the payload so future importers can avoid silent data loss. Notion documents `unsupported.block_type` as informational only; it is a plain string rather than a fixed enum, and unsupported block content is not exposed by the public API. The editor renders unsupported blocks as visible placeholders with imported type, optional source type, full warning list, and raw payload availability instead of hiding the row. Search text includes the imported type, source type, warnings, and raw-payload preservation state. Users can still duplicate, delete, or deliberately convert the block through normal block handles or the placeholder conversion controls. Conversion is explicit because it replaces the unsupported payload: summary conversion creates a paragraph with visible metadata, while JSON-code conversion writes the preserved raw payload or fallback metadata as editable text for review.

Block colors use the public Notion color names stored in the block payload. Text edits, to-do toggles, toggle open state changes, callout edits, table of contents color changes, conversions between color-capable block types, and duplication preserve the selected color. Rust and TypeScript validators reject unsupported color names before they are treated as typed Notes data.

Trashed pages keep their `in_trash` state in SQLite and are hidden from the normal page list and Archive. Trashing or restoring a page applies to the reachable page subtree so child pages do not remain active under a trashed parent. Directly trashing a nested page also hides its paired child-page block from the parent document, and restoring it reveals that block only when the original parent is still active. The sidebar exposes a Trash view that lists trashed page metadata, supports local search, restores a page by setting `in_trash` back to false through the same Tauri command boundary, and permanently deletes a trashed page after confirmation. If a restored page's stored parent is missing, archived, or still in Trash, the page is promoted to the workspace and the Trash view warns about the known parent-in-Trash case before restore. Permanent delete is a local Ganbaru AI recovery action, not a public Notion API operation. It removes the page subtree, paired child-page blocks, and page body blocks in one Rust transaction after confirmation. Restored pages are selected and loaded immediately. Page history retention is configured from the page header history disclosure.

## Backlinks and daily or project notes

Daily notes and project notes remain planned. They should be implemented as page properties, relations, templates, and derived indexes on top of the same page and block graph.

Daily and project note categories are conventions over Notes pages, not separate markdown folders and not separate data models.

## Sync and collaboration

Local editing is SQLite first. Future sync can layer CRDT state over the same page and block graph, but it must preserve SQLite as the local canonical store and keep markdown as a derivative format.
