# Chat

Chat is Ganbaru AI's project-owned interface for coding agents installed and authenticated by the user. It gives Codex, Claude Code, Cursor Agent, Grok, and OpenCode one consistent interface while preserving each provider's native sessions, models, approvals, questions, plans, and safety behavior. Ganbaru does not proxy prompts through a hosted service.

The provider transport and broader AI architecture live in [AI integration](ai-integration.md). Security invariants live in [security](../data/security.md). This document defines the user-facing Chat product.

## Scope

Chat supports:

- Automatically discovered local instances for implemented provider families plus explicitly configured provider instances.
- Multiple durable conversations per Ganbaru Project, each fixed to one project working folder.
- Durable local threads, drafts, attachments, search, archive, and restart recovery.
- Streamed assistant messages, reasoning summaries, commands, file changes, tools, tasks, warnings, usage, and cost when the provider reports them.
- Build and Plan interaction modes when supported.
- Native approvals, structured questions, steering, queued follow-ups, interruption, and force stop.
- Bounded file browsing, changed-file inspection, thread terminals, terminal context, and Git checkpoints.
- Wide, compact, detached, increased-font, reduced-motion, keyboard, screen-reader, and minimum-recovery layouts.

Remote clients, Slack, a general BYOK assistant, hosted execution, embedded web preview, branch publication, and pull-request automation are separate future surfaces.

## First use

On the first Chat load for a vault in each app session, Ganbaru runs one bounded discovery pass for every implemented provider family that is not configured or explicitly opted out. It checks each family's known command names on the application path and conventional user CLI directories, including standard pnpm, npm, Bun, Cargo, and Volta locations. When it finds an installed CLI, Ganbaru creates a default instance with the resolved device-local executable path, reuses the CLI's normal home and existing authentication, probes its status, and caches its model catalog when available. Refresh all repeats discovery for newly installed families, then updates the health and available model catalog of every configured provider. Native catalog metadata remains authoritative: Ganbaru preserves stable raw IDs while showing resolved versioned names and only exposing effort levels supported by each model. A person who already installed and authenticated a supported provider can select a project and start in its managed folder without configuring a path.

Refresh all forces a new discovery pass before it re-probes every configured instance, so a CLI installed after Ganbaru started or after the first Chat visit appears without resetting application data. An installed CLI with a broken package, unsupported version, missing authentication, or another probe problem remains visible with a recovery status instead of being treated as absent. A command that is genuinely missing is not added.

If no supported CLI is available, Chat directs the user to provider setup and official installation guidance. The advanced provider setup remains available for additional accounts, custom homes, arguments, environment variables, and credential references. Removing the last instance for a family records an explicit opt-out so later automatic scans do not recreate it. Adding an instance manually enables the family again. The model picker lists unconfigured implemented integrations as setup actions inside the corresponding company subsection even when only one integration is currently configured.

The first-use flow is:

1. Create or select a project. Its managed folder already exists.
2. Open Chat from Projects or the Chat tab. The shared project and remembered available working folder are already selected and visible.
3. If automatic discovery finds a healthy provider, review the visible provider, model, permission, and Build or Plan choices and send immediately. Otherwise, provider setup is the only blocking recovery step.

Failed probes preserve entered fields. Missing folders, changed repository identity, unavailable providers, unsupported capabilities, and another device without a binding have distinct recovery actions. Automatic discovery never supplies credentials, changes the CLI home, installs software, chooses Full access, or hides the active provider and model from the composer.

A fresh draft restores the last available working folder for the shared selected project, then falls back to its managed folder. Provider preference is stored per working folder. If it does not identify a healthy provider, Chat selects the first healthy discovered provider and that provider's strongest available built-in model, using a provider-resolved default when one exists. Ask for approval is the initial permission mode. When no provider is configured, the trigger remains Choose provider and opens the model picker directly. Opening an existing thread seeds the composer from that thread's effective provider, model, options, and modes before its persisted draft finishes loading. Switching threads saves the prior draft without exposing an empty selection or allowing loading state to overwrite the selected thread's configuration.

Chat settings separate Providers, Models, and Behavior into compact tabs. Project working folders and their provider preferences belong to Project settings. New external assignments use one native picker. Rebinding opens at the current folder, or its nearest available parent if the folder moved or was removed.

## Timeline

The timeline renders provider-neutral projections from durable canonical events. User messages retain exact text, managed attachments, immutable file mentions, bounded terminal context, time, and checkpoint-aware restore entry points. Provider lifecycle echoes of the submitted user message remain in canonical history but do not create a second timeline row. The user participant identity uses the folder-local Profile display name and profile image, with initials as the image fallback. Assistant messages use sanitized Markdown, safe external links, bounded images and tables, incremental content, code copy and wrap controls, duration, effective model, token usage, cost, and changed-file summaries when known. Intermediate assistant commentary uses the same paragraph treatment as the final answer. It remains normally visible while it is the latest live state, then retains its chronological position as a plain paragraph when earlier work is viewed inside the settled process disclosure. It never receives an activity icon, an Assistant response label, a nested disclosure, monospace output styling, or a message-level Copy action. Each model turn resolves the catalog display name for its effective historical model and uses the model company's local mark in a softly rounded square avatar. The same provider avatar treatment is used throughout Chat and Chat settings. Provider avatars have no border, use a pure white background, and preserve the same logo colors in every theme. Anthropic uses its warm orange background and off-white mark instead of the general white surface. The model picker is the only exception and uses unboxed monochromatic company marks. A missing catalog row falls back to the stored model id while still inferring a known model company when possible.

While a turn is active, the model participant block accumulates completed actions, running actions, and intermediate assistant paragraphs in chronological order. Thinking… is the fallback transient row. When a provider explicitly designates a public reasoning summary, the latest bounded summary replaces that generic label while it is live. Raw reasoning text is never promoted into the conversation. The next real paragraph or action replaces the current transient row, while all earlier real work remains visible. Every consecutive real-action run, including a single completed action, folds under one localized semantic summary such as Ran a command or Edited files, read files, and ran commands. The summary combines mixed action kinds, pluralizes repeated kinds, uses a representative action icon, and keeps the full row clickable while placing its chevron immediately after the summary text. Provider titles, exact commands, paths, queries, and tool names remain inside the expansion instead of dominating the conversation scan. Command details render a typed execution surface with the shell command, working directory, streamed or aggregated output, duration, exit code, and final status when those fields are reported. A completed command without provider-reported stdout says No output inside that execution surface. It is not presented as a provider failure. File-change items retain their structured paths, kinds, bounded patches, and line counts. Changed-file summaries open the Changes inspector for the exact historical turn. After the turn settles, the compact turn disclosure uses the same semantic action summary, while stopped and failed states remain explicit. A completed turn with only transient private reasoning and a final answer has no process disclosure because no user-visible work occurred. Expanding a disclosure restores the same commands, output, file changes, tools, web activity, images, tasks, hooks, warnings, failures, and intermediate assistant paragraphs that were visible live. Long expanded histories stop growing after a bounded, viewport-aware height and scroll internally. Directional top and bottom fades appear only while more content remains in that direction. Transient reasoning rows are omitted from settled history. Provider message phases identify final answers when available. Providers without phases use the last assistant message at settlement as the compatibility fallback. The final answer is rendered below the process summary. Both belong to the same model participant block and content edge, so agent-specific detail does not fragment or progressively indent the conversation. The only message-level Copy action appears beneath this settled final answer, reports success visibly, and uses a document fallback when the WebView Clipboard API is unavailable. Plans use an inline section in the same message flow, rather than a separate highlighted card, while retaining continue planning, implementation in a later turn, and dismissal. Interrupted and failed turns remain readable and accurately labeled.

Short conversations stay anchored to the bottom of the available timeline above the composer, so the first message starts near the place where the conversation continues. As the thread grows beyond the available space, earlier messages move upward into the normal scroll history. Virtualization uses measured rows and stable IDs. Prepending older pages preserves the visible anchor. Scrolling away during streaming disables follow mode, shows unread work and Jump to latest, and never forces the reader to the end. Long threads may show a minimap in a safe side gutter.

Live Thinking, Running, Reading, Editing, and comparable statuses use a slow, low-contrast text shimmer sized to the rendered label, so short placeholders and longer actions receive the same visible pass. Thinking is an iconless transient placeholder aligned to the normal assistant text edge, while concrete actions retain their identifying icons. A provider-completed reasoning item retains the live shimmer while it remains the current Thinking placeholder of an active turn. The highlight travels completely beyond the text before a quiet pause and the next pass. Completed process rows retain the shimmer's muted off color. Reduced-motion and forced-color preferences receive a static emphasized status.

Provider change notifications are coalesced to one serialized refresh per paint frame. Rust also batches adjacent compatible content deltas. This preserves durable sequence ordering without token-level SQLite reads or layout storms.

## Composer and provider interaction

The optimistic send transition is synchronous after local selection checks. Draft persistence, mention revalidation, native dispatch, and provider startup continue after the user row is visible and the composer is cleared. If preflight or dispatch fails, Chat removes the optimistic row and restores the recoverable draft.

The new-draft hero and docked composer share one persistent controller, so responsive layout changes do not replace the draft or undo state. Draft persistence includes provider-facing Markdown, versioned rich content, mentions, attachment references, and explicit provider, model, trait, safety, and internal interaction selections. Existing plain-text drafts remain valid when rich content is absent or invalid. A sent user message appears optimistically in the conversation as soon as local validation completes, including for the first turn while provider startup is still in progress, and is replaced by the matching durable row without duplication. The docked composer floats over a protected bottom timeline inset measured from its current rendered height, with only a compact reading gap above it. Its prompt is the dominant surface, while attachments, bold and italic formatting, provider and model, traits, safety, context, and Send or Stop form one compact footer. Bold and italic work through visible controls and the standard Ctrl+B and Ctrl+I shortcuts, and serialize to Markdown when sent. The dependency-free editor controller is the only owner of nodes inside the editable root. It lets the browser retain temporary IME DOM until composition ends, then reads, validates, normalizes, and restores the document and selection. Svelte owns only the surrounding shell. The prompt uses the available horizontal space up to its readable maximum, shows two text rows when empty, and grows internally up to ten rows before scrolling. Shift+Enter inserts a soft line break with the same line spacing and caret metrics as surrounding text. Prompt text, conversation messages, model trace summaries, and their icons share one readable type scale, while timestamps, token counts, and other secondary metadata remain smaller. While the person remains at the end of the conversation, streamed growth pins directly to the latest content instead of queuing smooth-scroll animations behind incoming updates. Expanding an existing timeline disclosure instead preserves the triggering row's viewport position. Its height eases open so later rows move down continuously, while the revealed detail fades and settles into place. Collapsing reverses the same motion. The scrollbar thumb remains visually continuous while the animated disclosure changes the scroll extent. Reduced-motion preferences receive an immediate state change. The circular Send or Stop action remains inside the composer boundary at every supported width. This keeps routine conversation immediate without hiding the selections that define provider behavior.

Images can be chosen, pasted, or dropped. Screenshot paste accepts both clipboard file lists and clipboard item representations, supplies a safe filename when the clipboard omits one, and uses the browser clipboard image API as a user-initiated fallback. The composer shows removable image thumbnails before send, and sent messages retain those thumbnails in conversation history. Selecting a thumbnail opens the same focus-contained gallery from either location, with previous and next navigation, zoom in, zoom out, reset, keyboard shortcuts, and a scrollable viewport for inspecting a zoomed image. The preview returns focus to its originating thumbnail when closed. Managed image bytes remain local and are adapted to each provider's native image input. Codex receives a bounded base64 data URL through its native image input, matching the app-server remote image shape. When the Codex catalog reports that the selected model is text-only, Ganbaru keeps the attachment in the composer and asks for an image-capable model instead of dispatching a filesystem task or silently switching models. File and folder mentions are searched inside the authorized project working folder and revalidated at send time. Bounded text selections can become managed text context. Ganbaru does not label arbitrary binary documents as universally supported attachments because provider and model input capabilities differ. Provider skills and commands are discovered through the selected provider's native protocol and bounded configuration files. The composer exposes provider, model, typed traits, safety, context, attachments, and Send or Stop directly. Plan is entered through the universal `/plan` command instead of a permanent footer or Advanced option. The `/plan` and `/build` prefixes select the corresponding provider-neutral interaction mode and are removed before the remaining request is sent. Provider and model selection share one keyboard-accessible picker with recognizable local brand marks, provider status, search, and model descriptions. The picker lists healthy configured instances, configured instances that need attention, and supported provider families that are not configured. Unavailable entries stay visible with a direct configuration path instead of disappearing from the picker. Selecting a model from another provider changes both values atomically for a draft. An existing thread requires a confirmed provider fork before the new provider and model are applied.

### Slash command palette

Slash commands activate only at the start of the composer. A slash inside ordinary prose remains text. The palette supports pointer, keyboard, and screen-reader selection and keeps the active option visible while navigating. All app, provider, project, and personal entries share one flat list without source headings. Every row uses a recognizable icon, a concise name, and a muted description on the same line. The menu does not repeat slash syntax or argument hints, and its bordered surface has no drop shadow. Source and argument metadata remain internal for collision precedence, filtering, and dispatch behavior. A stale entry keeps a compact visible status. The catalog is prefetched when the working folder, provider, task, or session boundary changes and remains cached for that boundary. Opening `/` never waits on provider or filesystem I/O. Ganbaru-owned commands appear immediately if a new provider catalog is still loading, and provider entries join the open palette when ready.

Selecting a command performs the action implied by that command instead of treating every command as message text. Control actions execute directly, informational actions open an anchored panel above the composer, provider turns start through their native operation, and commands requiring input switch the composer into a named mode. None of these paths insert slash syntax into the editor. Goal shows a target icon and Goal label in the footer, changes the placeholder to request an objective, and replaces Plan with Build. Discovered custom commands with argument metadata use the same input mode. Their hidden prefix is retained for retry while the person-facing draft remains plain text. Commands reject attachments and file mentions instead of silently dropping that context. Skills remain prompt content and therefore insert their value into the editor.

Ganbaru-owned commands perform shared UI actions without pretending that a provider implements them. `/plan` and `/build` select the interaction mode. Plan appears as a dismissible mode in the composer footer, while Build is the normal mode and does not add persistent chrome. `/model` opens model controls, `/permissions` opens safety controls, `/status` opens a structured provider, session, model, account, context, and rate-limit panel above the composer, and `/changes` opens the changed-file inspector. The Status panel never becomes timeline content. These shared names take precedence and suppress a duplicate provider catalog entry, so selecting and typing the same visible command cannot produce different behavior. Selecting one of these commands removes it from the prompt and preserves focus. Typing the complete command and pressing Send performs the same action. A mode command followed by request text changes the mode and sends only the request text.

Provider commands use the most authoritative available catalog and transport:

- Codex exposes only embedded actions that Ganbaru can execute through app-server. Compact calls `thread/compact/start` without creating a user message. App-server's `contextCompaction` lifecycle becomes one durable neutral activity row in the timeline. MCP calls `mcpServerStatus/list` and renders the bounded server, authentication, and enabled state in a structured panel above the composer, without creating user or assistant messages. It works from a new draft as well as an existing task. Ganbaru reuses the task's live app-server when available, otherwise it opens a bounded provider connection in the selected working folder and omits `threadId`. Code review calls `review/start`, and Goal uses the thread goal methods after entering its composer mode. Terminal-only Codex TUI actions are not copied into the embedded UI. See the official [Codex app-server reference](https://developers.openai.com/codex/app-server/).
- Claude Code uses the command list returned by SDK `initialize`. Commands are sent through the SDK control transport exactly as Claude documents for programmatic slash commands. Compact executes immediately without a visible user message, and its `compact_boundary` system event becomes the same neutral timeline activity used by Codex. A small documented fallback catalog remains visible before the first session, and the live initialization list replaces it when available. See the official [Claude Code SDK slash command reference](https://code.claude.com/docs/en/agent-sdk/slash-commands).
- Cursor and Grok use ACP `available_commands_update` as a full replacement catalog. Ganbaru sends the selected command as a normal ACP text prompt, which is the protocol-defined execution path. It does not copy terminal-only commands from either CLI. See the official [ACP session update type](https://agentclientprotocol.github.io/typescript-sdk/types/SessionUpdate.html).
- OpenCode reads `GET /command` from the workspace-scoped server and executes a matching slash request through `POST /session/:id/command`. Templates containing `$ARGUMENTS` or positional placeholders such as `$1` enter composer input mode. Other prompts continue through the asynchronous prompt endpoint. See the official [OpenCode server API](https://dev.opencode.ai/docs/server/) and [custom command reference](https://opencode.ai/docs/commands/).

Before a live provider session exists, Ganbaru may also read documented command locations inside the authorized workspace and effective provider home. Claude uses `.claude/commands`, Cursor uses `.cursor/commands`, and OpenCode uses `.opencode/commands` or `.opencode/command`. User-level Claude and OpenCode command folders are also supported. Discovery reads only bounded Markdown metadata, skips symbolic links, limits traversal depth and entry counts, preserves nested namespaces, and never turns a discovered file into a generic filesystem capability. Live provider catalogs take precedence over fallback and file-derived entries with the same command name. Stale fallback entries remain visibly marked so the provider can accept or reject them when sent.

Grok uses the installed `grok` CLI through ACP with `grok agent stdio`. Ganbaru preserves the CLI's cached login or uses the configured `XAI_API_KEY`, identifies itself through `GROK_OAUTH2_REFERRER`, and reads the current and available model IDs from ACP session setup. Model changes use `session/set_model`. The private xAI structured-question methods are normalized into the same durable question flow as other providers. The xAI prompt-completion notification can settle a turn when the corresponding prompt RPC remains open, without leaking the abandoned request slot.

Sending writes the user message, turn, attachment references, and idempotent command receipt before dispatch. A launch failure therefore leaves recoverable durable history with Retry, Edit into a new draft, and Change provider actions. A later send reuses a ready native session, but restarts or resumes a stopped or failed session even when its runtime snapshot still contains a stale session identity. Codex resume accepts the successful `thread/resume` response for the exact stored provider thread and does not require the fresh-thread-only `thread/started` notification. Structured native errors retain their provider message in the composer instead of being stringified as an opaque object.

During active work, the provider capability decides whether a prompt steers the turn, becomes a durable queued follow-up, or remains an unsent draft. Stop is idempotent and has a bounded stopping state. Force stop is explicit. Approvals expose only choices offered by the provider and never choose a permissive default. Structured questions preserve partial local answers and validate required fields before submission.

## Permission modes

The composer describes four permission choices. Ask for approval is selected for a fresh draft. It lets the provider edit within the selected workspace and asks before external file access, network access, or another provider-defined escalation. Approve for me keeps the same workspace boundary but sends eligible escalations to the provider's native safety classifier. Full access uses the provider's native unrestricted mode. Custom defers to the selected provider's own permission configuration without translating it into a Ganbaru policy. During an active turn, the composer does not add a separate mode-status sentence above the prompt.

| Permission choice | Codex | Claude | Cursor and Grok | OpenCode |
|---|---|---|---|---|
| Ask for approval | Workspace sandbox with user review | `acceptEdits` | ACP approval flow | Ask rules with workspace edits allowed |
| Approve for me | Auto-review | `auto` permission mode | Unavailable | Unavailable |
| Full access | Unrestricted sandbox | `bypassPermissions` | ACP approvals accepted automatically | Allow rules |
| Custom | Effective `config.toml` configuration | Effective `settings.json` rules and default mode | Effective `cli-config.json` or `config.toml` permissions | Effective `opencode.json` or `opencode.jsonc` permissions |

Approve for me is unavailable when a provider does not expose a native action classifier. Ganbaru does not simulate it by automatically accepting generic provider requests. Managed provider policy, explicit deny rules, and provider eligibility can still restrict a selected mode.

Full access and Custom trust are device-local and require confirmation for the exact provider instance and working folder. Custom uses the same trust boundary because every supported provider configuration can grant unrestricted access. Codex resolves its effective sandbox and approval settings. Claude starts without a permission-mode override so its settings precedence and `permissions.defaultMode` apply. Cursor and Grok leave native configuration enforcement in control and do not auto-resolve approval requests. OpenCode creates or resumes the session without replacing its configured permission rules. The active turn keeps its permission snapshot even if a later draft changes modes. Provider capability differences remain visible and disabled rather than simulated.

Chat settings provides a device-local editor for the documented user configuration and global instruction files of every configured coding-agent instance. It does not translate one provider's format into another or present a shared synthetic configuration. Codex exposes `config.toml` and `AGENTS.md` from its effective home. Claude exposes `settings.json` and `CLAUDE.md` from its config directory. Cursor exposes `cli-config.json`; its global user rules remain in Cursor settings because Cursor does not document a standalone global rules file. Grok exposes `config.toml` and `AGENTS.md` from `GROK_HOME` or its default home. OpenCode exposes its global `opencode.json` or `opencode.jsonc` and `AGENTS.md`, including an explicit `OPENCODE_CONFIG` override when configured.

The provider mapping follows the official [Codex configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference), [Claude Code permissions reference](https://code.claude.com/docs/en/permissions), [Cursor CLI permissions reference](https://docs.cursor.com/cli/reference/permissions), [Cursor rules reference](https://docs.cursor.com/context/rules), [Grok permissions reference](https://docs.x.ai/build/features/permissions), [Grok project rules reference](https://docs.x.ai/build/features/project-rules), [OpenCode permissions reference](https://opencode.ai/docs/permissions), and [OpenCode rules reference](https://opencode.ai/docs/rules/).

The editor reads and writes only backend-resolved file identifiers for the selected provider instance. The webview cannot submit an arbitrary path. Reads and writes accept UTF-8 text up to 1 MiB, reject symbolic links, and use content revisions to prevent overwriting a file changed by another process. Saves create missing parent directories, use restrictive permissions for new files, and replace the target through a sibling temporary file. Changes affect new provider sessions; an already running provider is not silently restarted.

## Inspector, terminal, and checkpoints

The wider right inspector remains closed until the person opens it, even when a full column fits. Smaller layouts keep the inspector available as a sheet without covering the conversation by default. Opening or switching chats does not reveal the inspector or bottom dock automatically. The right inspector and bottom dock render the same workspace-panel component with different initial tabs. The compact tab uses the selected filename when a file is open, and its add button opens Terminal, Changes, Plan, or Files on demand instead of reserving permanent navigation for every tool. The add menu renders above clipping containers, measures the available viewport space, and opens upward when it cannot fit below its trigger. A selected workspace draft owns inspector state before its first message, so the file tree can browse the bound folder immediately instead of requiring a persisted thread. Changes distinguishes provider-reported and Git-observed paths, preserves rename and binary metadata, and shows bounded unified or fitting split diffs with file-type icons, stable line gutters, and compact scope controls.

Files use a compact, lazily loaded tree on the left and a code editor on the right. The tree can be hidden, keeps folders independently expandable, and virtualizes large directories instead of mounting every entry. The editor virtualizes source lines, applies safe local syntax tokenization, and uses coding-font and line-number conventions. A repository-owned SVG icon set generated from a pinned `vscode-icons` revision provides recognizable, color-preserving icons for common languages, frameworks, tools, infrastructure, data, media, exact filenames, compound suffixes, and lockfiles. Unknown formats retain a neutral fallback. Each generated icon passes through Vite's asset pipeline and is bundled as a same-origin local image, so desktop WebViews do not depend on cross-document SVG fragment support or a runtime network request. Search, ignored-file visibility, external opening, path copying, and file or selection attachment remain available as icon actions. Binary, oversized, invalid UTF-8, traversal, and symlink-escape paths remain unavailable.

The bottom dock remains closed until the person opens it. When opened for a workspace draft, it starts with a running Terminal. The draft allocates its future thread ID before the first message, and the first send persists that same ID, so its terminal remains attached without being recreated or transferred. One tab row holds terminal sessions and any Changes, Plan, or Files panels the person adds through the adjacent add menu. In both the bottom dock and right inspector, every tab has the same moderate fixed width and can be smoothly dragged left or right into one shared order. The tab strip scrolls horizontally when its fixed tabs no longer fit, while panel controls remain reachable. Middle-clicking a tab closes it with the same safeguards as its close button, including confirmation for a running terminal, and draggable tabs retain the normal pointer instead of advertising a special drag cursor. Right-clicking any tab opens a compact, shadowless rename panel with save, cancel, and reset actions. The keyboard context-menu shortcut opens the same editor. Custom names belong to that tab in its thread session, and reset restores the current automatic label. This avoids stacked tab bars and permanent tool tabs while keeping every panel available without replacing the conversation or right inspector. Terminals are thread-scoped pseudoterminals owned by Rust. Their canonical names retain the local user, device, and workspace path for terminal context metadata, while the automatic tab label shows only the path beginning at the home-relative `~` when available. Long names fade at the tab edge, and a terminal can be closed from the tab on hover. Terminal panels do not expose restart, clear, or context utility toolbars. Tabs retain bounded sequenced output. The terminal resolves theme colors and uses a cross-platform coding font stack with regular output weight instead of inheriting the application text font or relying on a CSS variable that xterm cannot resolve. Multiline paste and closing a running session retain explicit confirmation. The webview never receives a generic shell command capability.

Git workspaces capture hidden refs under `refs/ganbaru-ai/chat/` using an isolated index. Capture does not move HEAD, change branch, touch the real index, alter staging, or modify working files. Restore first produces a revision-bound preview with affected files and warnings. Native provider rollback must succeed before filesystem restore when available. Confirmed restore preserves the target branch and staging state, invalidates later conversation projections durably, and queues only exact later refs for cleanup.

## Data ownership and retention

| Data | Location |
|---|---|
| Project working folders, threads, canonical events, projections, drafts, attachment metadata, receipts, checkpoints, cleanup | Active vault SQLite database |
| Managed image and text attachment bytes | Active vault `assets/chat/attachments/` |
| Absolute workspace paths, executable paths, provider homes, probe caches, diagnostics, full-access trust | Device-local application state |
| Provider tokens and passwords | Operating-system credential store behind opaque references |
| Provider processes and terminal sessions | Memory owned by the current app process |

Archive is reversible. Permanent deletion requires confirmation, removes owned conversation rows, and records deferred attachment or checkpoint cleanup before destructive external work. Attachments remain while referenced and use a grace period before file deletion. Checkpoint cleanup always names an exact hidden ref.

Optional protocol diagnostics are off by default, redacted, bounded, device-local, and retained for 1 to 30 days. Users can inspect captured field categories, export the same redacted representation, delete diagnostics immediately, stop all Chat processes, and rebuild projections only when runtime and durable-turn safety checks pass.

## Responsive and accessible behavior

Chat keeps the fixed explorer, conversation, and inspector columns while they fit, moves the inspector to a sheet next, then presents the explorer as a focus-contained sheet below the Chat header. A collapsed column explorer leaves its 2.75 rem restoration strip. At the 280 by 180 recovery floor, the header and one primary surface remain usable, and every essential action remains reachable. Layout changes preserve the selected thread, draft, undo state, timeline anchor, search, explorer expansion, inspector state, terminal state, approvals, and questions.

The inspector and bottom-dock separators support pointer and keyboard resizing with accessible values and reset actions. The explorer has no resize affordance. Pointer resizing is coalesced to animation frames, and panel transitions are disabled during the gesture so the tree and editor track the pointer without delayed interpolation. Modal surfaces enter useful focus, contain Tab navigation, and restore their trigger. Statuses use text or shape in addition to color. Live regions announce provider state, settled responses, approvals, questions, errors, and Stop without reading every streamed delta. English and Spanish catalogs use locale-aware formatting. Reduced motion removes smooth scrolling, transitions, and progress animation.

## Performance contract

Chat is lazy-loaded and does not probe or start providers at app boot. The first Chat load may run the bounded provider discovery described above. Each active vault runs that automatic pass at most once per app session, and ordinary Settings refreshes reuse cached provider state. Refresh all is the explicit forced rescan. The deterministic benchmark fixture uses cached provider state. The `dense-chat-v1` benchmark covers 20 projects, 100 threads, 2,000 turns, 4,000 messages, 4,000 activities, 1,000 plans, 500 attachments, 200 checkpoints, and 10,000 canonical events in the isolated benchmark database.

The benchmark measures route activation, recent-thread switching, latest-page SQLite read and projection, loaded and indexed rail search, streamed paint cadence, app process-tree idle CPU, memory, and owned process stop. The target latest-page read is normally below 100 ms, indexed search below 150 ms, normal stop below two seconds, and streaming is coalesced to paint frames. Performance results are recorded only from the installed release benchmark harness using the method in [Performance benchmark harness](performance-benchmark.md).
